# お問い合わせフォームの営業対策（営業目的の送信に関する特約）

フォーム経由の営業が増えたため、[株式会社フォルテのお問い合わせページ](https://forte.inc/contact/)を参考に
「営業目的の送信は禁止、送った場合は 1 件ごとに金額を請求する」仕組みを入れた（2026年10月1日）。

## 考え方

- 「営業を有料で受け付ける」のではなく、「禁止しているのに送ってきた場合の違約金」という位置づけ
- 実際に請求して回収することより、送る前に思いとどまらせる（抑止）ことに主な効果がある
- 本文はフォルテの文面を写さず、項目立て（適用・範囲・金額・支払い・撤回・記録と管轄）だけ参考にして書いた

## ページ上の構成（`/contact` と `/en/contact`）

1. お問い合わせ種別（ラジオ・必須）: ご依頼・ご相談／取材・登壇／その他。「営業」の選択肢はあえて置かない
2. 既存の項目とプライバシーポリシーの同意（name 属性は変えていない）
3. 特約への同意チェック（必須）: 金額をラベルの下にも書く。送信ボタンの直前なので、送る前に必ず金額が目に入る
4. 特約の全文はダイアログ（`#sales-terms`）。同意チェックの「営業目的の送信に関する特約」のリンクで開く

- 最初はフォームの上に「営業お断りと金額」の囲みを置いていたが、2026年10月2日に外した。
  金額を伝えるのは同意チェックのラベルの下の一文だけになっている
- フォームの幅はページの本文の幅（`--body-column`）に合わせている（個別の `max-w` は付けない）

## 特約のダイアログ（`src/components/Dialog.astro`）

- ブラウザ標準の `<dialog>` を `showModal()` で開く。後ろのページは操作できなくなり、
  Esc キー・× ボタン・「閉じる」ボタン・背景のクリックで閉じる。閉じるとフォーカスは開いたリンクに戻る
- 開くきっかけはボタンではなく `<a href="#sales-terms">` のまま（文中で普通のリンクとして折り返すため）。
  スクリプトがクリックを横取りして開く。`aria-haspopup="dialog"` でダイアログが開くことを伝えている
- `/contact#sales-terms` で開くと最初からダイアログが開いた状態になる。
  英語版の「Japanese original」リンクや、請求書のメールから特約を案内するときに使える
- 背景クリックで閉じる `closedby="any"` は Safari が未対応なので、同じ動きをスクリプトでも付けている
- JS が動かない環境では特約を読めない（ダイアログが表示されない）。
  フォーム自体が reCAPTCHA のために JS 必須なので、送信できる人は必ず読める、という前提で割り切っている
- 他のページでも使える汎用のコンポーネント。`<Dialog id="..." title="...">` の中に本文を書き、
  `<a href="#id">` を置けば開く。中に `<form method="dialog">` があるので、`<form>` の外に置くこと

## 金額の変え方

- `src/consts.ts` の `SALES_SOLICITATION_FEE_YEN` だけを変える。日本語・英語ページの表示がまとめて変わる
- 現在の 100,000 円はフォルテに合わせた **仮の値**
- 特約の本文を変えたら、末尾の「制定」の日付を「改定」に変えて更新する（英語版も）

## SSGForm 側の設定（管理画面で行う）

新しく増えた name 属性は次の 2 つ。日本語・英語フォームで同じ値にしている。

| name 属性                              | 送られる値                                                                 |
| -------------------------------------- | -------------------------------------------------------------------------- |
| `お問い合わせ種別`                     | `お仕事のご依頼・ご相談` / `取材・登壇のご依頼` / `その他`（英語版も同じ） |
| `営業目的の送信に関する特約に同意する` | 日本語版 `同意する（日本語版）` / 英語版 `同意する（英語版）`              |

SSGForm にはフィールドを登録する設定も「必須項目」の設定もない（2026年10月2日に公式の
[機能一覧](https://ssgform.com/features)と [FAQ](https://ssgform.com/faq) で確認）。
送られてきた name と値が、そのまま「name：値」の形で通知メールに並ぶ。

- **必須チェックは HTML の `required` だけ。** ブラウザを通さずに送るボットなどは素通りできる。
  同意チェックのない送信が届いたら、特約に同意していない送信として扱う
- **送信内容は SSGForm に保存されない。** 管理画面に残るのは送信があったことと件数だけで、
  再送信や CSV 出力もできない。届いた通知メールが唯一の記録なので、消さずに保管する
- 同意チェックの値は、通知メール上で「どの言語版の特約に同意したか」の記録になる
- 自動応答メールが SSGform 形式なら、2 項目は送信者への控えにも載る（同意した記録が相手の手元にも残る）

管理画面で確かめること:

- 通知メール・自動応答メールの本文が **カスタム形式** なら、2 項目を差し込みに足さないとメールに出ない。
  SSGform 形式なら何もしなくてよい
- **全角文字チェック** を対象の項目を指定せずに使っていると、ラジオ・チェックボックスが日本語の値を送るので、
  英語だけのスパムでも必ず通るようになる。項目を `お問い合わせ内容` に絞ると英語版からの英語の問い合わせが弾かれるので、
  使い方を決めて設定する
- 公開後に 1 回テスト送信して、通知メールに 2 項目が出ることを確かめる

## 営業が来たときの流れ（想定）

1. 通知メールで、特約への同意の値・送信日時・内容を確認する（通知メールは消さずに保管する）
2. 営業目的にあたるか判断し、あたる場合は入力されたメールアドレスへ理由を添えて請求書を送る
3. 支払期限は「受付月の翌月末日」と「請求書送付から 14 日後」の遅いほう
